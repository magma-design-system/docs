An application talks to people all the time: a field is missing, a list did not load, a change
was saved, a deletion needs a yes. A message works only when it is seen where people are looking,
understood, and answered when it asks something. Magma has a component for each kind of message;
this pattern decides which one goes where, with one rule:

**A message goes where the thing it talks about is.**

<PatternPreview id="messages" />

## When to use it

Whenever the application tells people what happened, or asks them something before going on:
the message of a field, a part of the page that failed, the result of an action, a decision, a
notice about the whole application. The other states of a screen in the same group, Messages
and states - nothing to show yet, loading - will have patterns of their own.
