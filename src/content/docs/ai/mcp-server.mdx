Magma ships an MCP server inside `@maggioli-design-system/magma`, the `magma-mcp` command.
The agent's client starts it in the project, and it answers from the version installed there:
the components and their API, the roles and the tokens, the classes of Magma's Tailwind theme,
the icons that exist, the sections of the guides, and the lint on a snippet before it is
written. It only reads: no tool changes a file.

A question to the server costs a short answer, where the same question to the guides costs a
file to read: the values of one prop instead of the guide of the component, the role for
"secondary text" instead of the color guide. And what the server answers is checked against
the package, not remembered.

## Set it up

There is nothing to publish or to install apart from Magma: the server runs from
`node_modules`, on your machine, through the standard input and output of the client. It is
not a remote service, and it is not one of the connectors of a chat app.

**Claude Code**: register the [Magma plugin](../claude-code/), which starts the server and
adds the skills. With the plugin, do not also write the entry below, or the server runs twice.

**Claude Code without the plugin**: `.mcp.json` at the root of the project, committed so that
the whole team gets it; Claude Code asks once before it starts a server of the project.

```json title=".mcp.json"
{
  "mcpServers": {
    "magma": { "command": "npx", "args": ["--no", "magma-mcp"] }
  }
}
```

**VS Code with GitHub Copilot**: `.vscode/mcp.json`.

```json title=".vscode/mcp.json"
{
  "servers": {
    "magma": { "type": "stdio", "command": "npx", "args": ["--no", "magma-mcp"] }
  }
}
```

**Cursor**: `.cursor/mcp.json`, with the same entry as Claude Code under `mcpServers`.

Merge the entry into the file when it exists, never replace it. Keep `--no`: it makes `npx`
run the installed command and stop when there is none, for instance in a fresh clone before
`npm install`, instead of downloading whatever the npm registry has under that name. When the
client starts servers outside the root of the project, add `"--root", "<folder>"` to `args`.

The tools of the installed version, with what each one answers and the reading it saves;
the arguments that end in `?` are optional:

`check_markup` runs the [lint](../../development/lint/) with the ESLint, Stylelint and
parsers installed in the project: set the lint up first.

## When the agent calls them

The guide `agents/mcp.md` tells the agent when to reach for each tool:

- before writing a component, `find_component`, then `get_component` and `get_usage`;
- before a color, a spacing or a class, `list_tokens`, `suggest_role` or `explain_class`;
- before an icon, `find_icon`;
- after writing, `check_markup`, then the lint of the project;
- after the setup, or when something does not render, `check_setup`;
- when no tool answers what the task needs, or an answer says Magma has nothing for it
  (`gap`), it tells you, carries on, and at the end proposes an issue on Magma for each
  missing answer: it opens one only once you agree.
