Il plugin di Magma porta Magma in Claude Code in un passo: avvia il
[server MCP](../mcp-server/) della versione installata e aggiunge cinque skill, procedure che
Claude segue per fare un lavoro intero. Una skill dice quali strumenti chiamare e in che
ordine, e i fatti vengono dal server e dalle guide della versione del progetto: la procedura
è la stessa su ogni progetto, l'API è sempre quella installata.

## Registrarlo per il team

Scrivi il plugin nel `.claude/settings.json` del progetto, nel repository insieme al codice:
lo ha chiunque apra il progetto in Claude Code, nel terminale e nell'app desktop, una volta
che si fida della cartella. Unisci le chiavi al file quando esiste già.

```json title=".claude/settings.json"
{
  "extraKnownMarketplaces": {
    "magma": {
      "source": { "source": "github", "repo": "magma-design-system/magma" },
      "autoUpdate": true
    }
  },
  "enabledPlugins": { "magma@magma": true }
}
```

Il plugin è servito dal repository di Magma su GitHub: non c'è altro da installare. Segue il
branch principale del repository e non ha una versione sua, perché le sue skill non
contengono dati: quello che cercano viene dal Magma installato nel progetto.

Per provarlo da solo prima del team, in una sessione di Claude Code nel terminale:

```text
/plugin marketplace add magma-design-system/magma
/plugin install magma@magma
```

I plugin si caricano all'avvio di una sessione: apri una nuova sessione dopo averlo
registrato.

## Le skill

| Skill                  | Chi la avvia                                                 | Cosa fa                                                                          |
| ---------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| `/magma:setup`         | Tu, o Claude quando gli chiedi di installare                 | Installa il pacchetto del framework, segue l'installazione di `AGENTS.md`        |
| `/magma:ui`            | Claude, quando lavora sull'interfaccia del progetto          | Trova il componente, la sua API, i ruoli e le icone, controlla prima di salvare  |
| `/magma:review`        | Tu, o Claude dopo un lavoro sull'interfaccia                 | Lancia il lint sui file modificati, poi controlla quello che nessuna regola vede |
| `/magma:migrate`       | Tu                                                           | Porta un progetto da Magma 1 a Magma 2 con il codemod                            |
| `/magma:pattern-layer` | Tu, o Claude quando un prodotto vuole restringere un pattern | Scrive il livello di un pattern per il prodotto, poi lo verifica                 |

`/magma:setup` finisce con `check_setup` e una build. `/magma:review` riporta ogni problema con
la riga, la regola o la sezione della guida, e la correzione, e cambia il codice solo se glielo
chiedi. `/magma:migrate` lancia prima il codemod come prova a secco, scrive solo su un albero
git pulito, poi lancia la build e il lint.

`/magma:ui` chiede `get_pattern` prima di costruire un flusso che dice qualcosa alla persona o la
fa aspettare o decidere, e segue il caso che riceve; `/magma:review` controlla ogni flusso di
questo tipo nei file modificati rispetto al suo caso e alle regole che valgono sempre.
`/magma:pattern-layer` ti chiede le scelte aperte e le situazioni del prodotto, una alla volta,
scrive `magma/patterns/<id>.md` e lo verifica con `get_pattern` finché non viene applicato: come,
in [Progettare per il tuo prodotto](../design-for-your-product/).

Dopo un comando, scrivi su cosa lavorare: `/magma:review src/app/orders` rivede solo quella
cartella.
